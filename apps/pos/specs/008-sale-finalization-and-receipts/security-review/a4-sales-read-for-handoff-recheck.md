## 4. Findings and their disposition

| Severity | Finding                                                                                                                                                                                                                                                                                                                                       | Disposition                                                                                                                                                                                                                                                                                              |
| :------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| LOW      | **LOW-1: the reason set is wider than doc 20 §5.1.** The doc lists `no_session`, `sale_not_found`, `forbidden_field_in_request`. This slice also returns `role_denied` (RT-546 role gate, RT-741 ownership) and `invalid_input` (a malformed request).                                                                                          | Accepted: both are existing members of the closed enum, apply the one gate every `sales.*` read uses, and carry no sale field. The renderer treats every `refused` the same way (stop, neutral line). Doc 20 §5.1 should list them when it is next revised; no behaviour depends on it.                  |
| LOW      | **LOW-2: `pending` versus `sale_not_found` distinguishes "no sale for this handoff id" from "a sale for this handoff id in another scope or attempt".**                                                                                                                                                                                         | Accepted: it is what doc 20 §5.1 specifies, and it can only be observed by a caller who already holds a handoff id (an unguessable UUID of the payment on its own screen). A renderer cannot enumerate ids, and a hit discloses no sale field. Making a wrong scope answer `pending` would hide a real fault from the cashier. |
| LOW      | **LOW-3: `invalid_input` refusals are not audited.**                                                                                                                                                                                                                                                                                           | Accepted: malformed input, no data returned; the same posture as `sales.list` (`invalid_request`) and `sales.listRecent`.                                                                                                                                                                                |
| LOW      | **LOW-4: a damaged `tender_lines_summary_json` makes the projection throw.** `projectSaleForRenderer` is shared with `sales.read` and `sales.findByNumber`; `JSON.parse` there is unguarded, so a corrupt row rejects the invoke (the rejection message may quote stored text). | Accepted for this slice: the `sales` table is append-only and written only by the finalizer from typed values, so the case is latent; the projection is shared and outside RT-1322's scope. Not changed here. The renderer treats a rejection as the neutral line. |
| INFO     | The answer is the full `SaleSummary` (lines, seller name, scope ids) although Completion uses only `sale_number` and `short_number`, and the renderer asks up to 21 times per payment. | Accepted: it conforms to doc 20 §5.1 and reuses the one projection. A narrower projection is a possible later change; the cost is per-poll print and drawer reads of one sale. |
| INFO     | After a sale is stamped under a different operator (manager recovery, RT-441) a cashier session asking for it is refused `role_denied`. Completion then shows the neutral M-N5 line.                                                                                                                                                          | Accepted: fails closed and never claims a sale. It matches doc 20 §11 "own sales" and is not a new decision.                                                                                                                                                                                              |
