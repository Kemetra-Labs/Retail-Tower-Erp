### Added
- RT-1138 `[GATED: contract, migration]`, owner "Yes, implement" and contract shape confirmed in chat (2026-11-12): per-store cashier suspension (migration `0106`, new `cashier-suspensions.openapi.yaml`). A cashier with no stored state is not suspended, so existing cashiers are unchanged. Owners and tenant admins suspend and reactivate a cashier with `PUT` / `DELETE /api/v1/stores/{store_id}/cashiers/{user_id}/suspension` (session-only, audited as `cashier.suspended` / `cashier.reactivated`), and the Console lists a store's suspended cashiers. A suspended cashier is refused at admission and moves from `cashiers` to a new `suspended_cashiers` list in the POS roster (`pos-cashier-admissions.openapi.yaml` 1.2.0-draft, additive). It does not cut an open session; the POS does that on sync (RT-1139). New deploy grant script `cashier-suspensions-domain-grants.sql`; the POS and Admin Console contract PINs need a repin after merge.
