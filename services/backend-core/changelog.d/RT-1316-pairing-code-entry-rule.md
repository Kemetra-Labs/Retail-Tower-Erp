### Changed
- RT-1316 `[GATED]` contract description only, owner decisions 2026-11-10 ("Console codes only" for the POS entry rule, and "Yes, add to Phase 3"): the `posPairTerminal` request's `pairing_code` description (`pos-terminal-pairing.openapi.yaml` 1.7.0-draft) no longer says the code is opaque to the POS and sent exactly as entered. It now states the POS rule: whitespace and dashes are removed and the entry is upper-cased, and the result is sent when it is exactly 16 characters from the Console alphabet; any other entry, such as a generated bootstrap CLI code, is sent trimmed and otherwise exactly as entered. An owner-supplied bootstrap code that normalises to the Console shape is sent normalised, so it must be supplied in upper case without separators. The server still matches the SHA-256 of the exact value it receives. No wire, schema, pattern or length change.
